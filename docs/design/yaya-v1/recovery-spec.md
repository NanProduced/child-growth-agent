# 失败恢复规格（全场景）

原则（先于一切组件）：

1. **不确定 ≠ 失败 ≠ 成功**。结果不确定只有一种恢复方式：重新读取原操作回执。 [C] `review-client.tsx:292-328`
2. **用户资产不丢**：输入文字、已选图片、已核对选择在失败后保留；只有服务端确认写入后才清理。 [C] 需求 §3；`new-observation-client.tsx:294-297`（失败保留表单）
3. **恢复不自动重做写入**：任何恢复路径（刷新、重开、换设备、重新读取）都不自动重复提交。 [C] 需求 Q8、§5
4. **每一层分开反馈**：上传 / 分析 / 保存 / 归档各自有状态与回执；一层失败不谎报上层结果。 [C] 需求 §3.4
5. **守门不降级**：失败恢复不得跳过确认、指南依据、成人帮助或版本复核。

## 1. 场景矩阵

### 1.1 网络中断，输入未发送 / 发送失败

- 检测：`fetch` 抛错或 `navigator.onLine` 变化（仅提示，不作为判据）。
- 表现：输入区保留原文与附件缩略图；消息流出现 `发送没有完成，内容还在。 [重试]`。
- 动作：重试是显式点击；同一消息的消息 ID 不变，重试不产生重复用户气泡。
- 禁止：清空输入框；自动重发；把未发送消息显示为已送达。

### 1.2 写入结果不确定（网络在保存途中中断）

- 检测：写请求抛错（超时/断网），或响应到达但无法证明生效（缺少决定性回执）。 [C] `review-client.tsx:426-433、457-462`
- 表现：卡片从动作区切到**待核对卡**：`保存结果待核对` + `[重新读取核对]` + `不会自动重复提交归档。`
- 动作：`重新读取核对` 读服务端事实：
  - 已归档 → 完成态 + `重新读取后确认观察已归档；正在重新读取详情，请勿重复提交。` [C] `review-client.tsx:309-318`
  - 未归档 → 保留输入与选择，`可以核对后重试`。 [C] `review-client.tsx:320-322`
  - 读不到 → 继续待核对，不改变判断。
- 禁止：自动重发写请求；把“读不到”当成“没保存”；把待核对显示为成功。

### 1.3 已保存，但详情暂时读不到

- 检测：写回执为成功，但详情读失败（`saved_detail_unavailable` 语义）。 [C] `review-client.tsx:497-507`
- 表现：`这条观察已确认归档；详情暂时未读取到，正在重新读取。请勿重复提交归档或再次修改关联。` [C] `review-client.tsx:758-762`
- 动作：自动重新读取详情（只读）；教师可继续；不重新提交。已完成的其他分支（档案更新/关联写入）按回执如实显示。

### 1.4 逐图重试与部分图片失败

- 检测：上传失败（网络/大小/类型）、分析失败（模型超时/非法输出）。
- 表现：缩略图上的徽章：`上传失败 [重试]` / `分析失败 [重试] [继续用文字记录]` / `已上传 · 未分析`。
- 动作：只重试该图；其他图与其他字段不受影响；移除图片不回滚已保存的记录正文。
- 禁止：整批作废；把分析失败当上传失败；用假缩略图占位。

### 1.5 版本/前提变化（重新核对）

- 触发：教师修改后再改、指南 revision 变化、依据失效、目录版本不一致、班级资料在核对后变化。
- 表现：对应卡片出现 `有关联选择需要重新核对或移除，暂不能归档/提交。`；旧批准与旧决定不自动重放。 [C] `review-client.tsx:394-396、440-448`、`new-observation-client.tsx:279-283`
- 动作：重新读取最新事实 → 教师逐条重新核对或移除 → 才可再次批准。
- 禁止：静默沿用旧决定；自动合并冲突。

### 1.6 另一端已归档 / 状态冲突（409）

- 检测：写回执 409（如另一操作端已归档）。
- 表现：`正在重新读取服务端状态核对。` 然后依事实：已归档 → 完成态；未归档 → 保留选择可重试。 [C] `review-client.tsx:449-455`
- 禁止：报“失败”；覆盖对方结果。

### 1.7 批量部分完成

- 表现：批次条 `已保存 2 条 · 1 条待核对`；每张卡独立状态；已保存卡只读。
- 动作：`只处理未完成项`；重试仅作用于未完成卡；已保存项永不重发。 [C] 需求 §7 反例要求
- 失败恢复不得把整批回滚为草稿。

### 1.8 账号切换（清私有投影）

- 触发：登录另一个账号、会话失效后重新登录、退出。
- 表现：立即清空上一身份的私有投影：会话草稿、附件缩略图、待提交选择、未发送输入；不做缓存展示。 [C] `review-client.tsx:236-263`（viewerKey 变化清空）；`fetchWithAccountAuth` 403 事件 [C] `client.ts:77`
- 动作：新身份加载自己的历史；旧身份草稿不可恢复（除非服务端按账号保存草稿，属 DATA1 范围）。
- 禁止：跨账号复用草稿/附件/对象选择；用旧身份数据闪一下再换。

### 1.9 撤权/转班/停用后的历史内容

- 触发：会话仍有效但范围变化（转班、任教移除、账号停用、资源归属变化）。
- 表现：
  - 业务读取：403/401/409 语义卡；不显示旧范围数据。
  - 历史会话：显示受限投影卡 `当前账号不能查看这段内容`（不渲染具体幼儿/观察详情）；正式观察与仍被引用的图片不因聊天删除而删除。 [C] 需求 §5；[A] 受限投影粒度待 YAYA0-CONTRACT
- 动作：可继续一般教育问答（若角色允许）；写操作以服务端复核为准，迟到写入被拒。 [C] `access.ts:195-222`
- 禁止：靠聊天历史绕过权限；把受限展示成 404 或空。

### 1.10 基础设施与身份不可用

- 身份服务不可用（503）：fail closed，隐藏写入口，提示 + 重试；不渲染任何园所数据。 [C] `write-access.ts:27-29`
- 数据库读取失败：`读取暂未完成，请稍后重新读取；这不代表没有数据。` [C] `children/[id]/page.tsx:176、212`
- 计数未知：`null`=未获取，显示重试/未知；不得显示 0。 [C] PRODUCT.md 首页契约口径
- 模型超时：`整理没有完成，输入还在 [重试]`；不消耗教师已核对的选择。 [C] `llm.ts:375-379`

### 1.11 关闭、取消、删除

- 关闭面板/切页：不撤销任何已完成写入；`关闭聊天不会撤销已完成的写入。` 可作为关闭提示（轻提示，不阻断）。 [C] 需求 §3
- 取消上传/分析：停止该任务，保留原图与文字；不生成半成品草稿。
- 删除会话：只删会话/消息；正式观察、已归档关联与仍被记录引用的图片保留；不按对象前缀清空。 [C] 需求 §5

## 2. 图片管线状态机（上传/分析/保存/归档分开）

```
选择图片
  │
  ▼
待上传 ──上传失败──▶ 上传失败 [重试/移除]
  │
  ▼
已上传 ──分析失败──▶ 分析失败 [重试/继续文字]
  │
  ▼
分析完成（AI 解读，标注来源；不写入观察事实）
  │
  ▼
随记录保存 ──保存失败──▶ 图片未关联 [重试]
  │
  ▼
归档后随记录回看（对象引用；签名 URL 过期则刷新缩略图）
```

- 每一步都有独立徽章与文案；`分析完成` 后仍需教师选择关联对象/记录才进入保存。
- 共同照片被多记录引用时是**同一媒体对象的多个引用**，不复制文件、不复制事实。 [A] 具体引用模型归 MEDIA1

## 3. 幂等与防重复

- 所有主按钮：点击即禁用 + `正在保存…`；状态更新完成前不恢复。
- 保存失败恢复后再次点击才允许提交（同一操作 ID 复用，服务端幂等由 CONTRACT 定义）。
- 双击、迟到响应、旧请求代次不覆盖新状态：沿用现有 lookupKey/generation 模式。 [C] `new-observation-client.tsx:101-106、181-212`、`teacher-provider.tsx:24-33`

## 4. 给 QA1 的恢复测试钩子（未来，非本轮）

| 场景 | 可观测点 |
|---|---|
| 断网保存 | 待核对卡出现、写请求只发一次、重新读取后事实正确 |
| 已保存详情失败 | 完成态 + “详情暂不可读”，无第二次写请求 |
| 依据失效 | 决定卡阻断归档、要求重新核对、旧决定不重放 |
| 批量部分 | 只重试未完成卡、已保存卡不可再提交 |
| 切账号 | 旧投影立即消失、无旧数据闪现、历史为新身份投影 |
| 撤权历史 | 受限卡出现在历史，不渲染旧详情 |
