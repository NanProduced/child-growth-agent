# 消息与卡片规格（特殊消息 + 小芽姿态）

本文件定义助手消息区里的业务卡。三方向共用这些卡的内容与语义，差异只在承载方式（卡内/抽屉/分栏）。字段只描述“信息需求”，不冻结 DTO；DTO 归 YAYA0-CONTRACT。

## 1. 通用骨架

每张业务卡自上而下：

1. **标题行**：卡片类型 + 对象 + 时间/日期 + 状态徽章（附文字，不只用颜色）。
2. **事实区**：只放事实与来源；AI 生成的段落带 `AI 生成` 标记；教师原文与 AI 解读来源分开。 [C] `status-badges.tsx:34-45`
3. **核对区**（可折叠）：对象/日期/事实对照/图片归属/影响说明。
4. **动作区**：一个主按钮 + 次要按钮；主按钮在被点击后进入进行中并禁用重复提交。
5. **回执条**：只有服务端回执到达后，才把卡切到完成态；否则显示“待核对”。

规则：

- 卡片永远有稳定对象绑定；页面切换、会话滚动、恢复历史都不改绑定（`recovery-spec.md` §8）。
- 卡内动作幂等护栏：同一操作进行中，按钮禁用并给出 `正在保存…`；失败后允许显式重试，不自动重发。
- 任何“已完成”必须有回执内容（记录引用、结果、时间），不能只有模型文本。 [C] 需求 §7
- 卡片状态文本（建议固定）：

| 语义 | 文案 |
|---|---|
| 缺信息 | `还差一项：…` / `需要你选一下：…` |
| 待核对 | `请你核对` |
| 进行中 | `正在整理…` / `正在保存…` |
| 等回执 | `正在确认保存结果…` |
| 保存成功 | `已保存` / `已确认归档` |
| 部分成功 | `已保存 2 条，1 条待核对` |
| 保存不确定 | `保存结果待核对` |
| 权限不足 | `当前账号不能执行这个操作` |
| 模型失败 | `整理没有完成，输入还在` |

## 2. 特殊消息目录

### 2.1 多候选幼儿选择卡（歧义对象澄清）

- 触发：重名、指代不明（“他们俩”）、一条消息可能涉及多幼儿、或从页面带入的对象与聊天上下文冲突。
- 组成：候选列表，每项 = 情绪头像/首字 + 姓名 + 班级与学段 + （同名时）出生年月差异；底部 `都不是，重新说明`。
- 动作：点选即缩小到唯一对象，出现确认行：`对象：小满（芽芽班）` + `[用它继续]`。
- 禁止：自动选第一个；把“可能相关”的幼儿并入卡；静默替换已有卡片对象。
- 状态：候选来自当前范围读；读取失败出“重试”，不出空列表。 [C] 列表错误 vs 空态在 `new-observation-client.tsx:316-340、365-373`
- 固定文案：`有多个小朋友符合，请选择这次要用的对象` / `都不是，重新说明`。

### 2.2 观察准备卡（聊天内录入 / 表单接续共享同一草稿）

- 触发：用户说“记一条观察”“刚才小满……”，或从表单页带入的记录。
- 组成：对象、日期（原生 `input type="date"`）、情境（选填）、观察原文（白描提示 + 字数 ≥10）、图片缩略图条、发生时班级核对区。
- 班级核对四态：`正在核对这条观察发生时的班级…` / `发生时班级：芽芽班（按分班历史核对）` / `无法自动确定，请选择当时所在班级` + 班级下拉（含已停用）+ `重新加载班级` / 核对失败 + `重新核对`。 [C] `new-observation-client.tsx:412-501`
- 动作：`保存观察并继续整理`（主）；`先只保存原文`（次，同样走服务端保存原始记录）。
- 状态：保存成功后出“观察已保存，原文将不可修改”，并接 AI 整理或进入 Review。 [C] `new-observation-client.tsx:288`
- 禁止：把缺选班级渲染成系统错误；保存前进行 AI 分析；原文保存后提供编辑入口。
- 固定文案：与现有录入页一致：`用白描方式记录幼儿的具体行为与语言。保存后原文不可修改`。

### 2.3 多人批次卡（多幼儿独立记录）

- 触发：一条输入明确描述多个幼儿的不同行为，或教师选择“拆成多张卡”。
- 组成：批次条 `本批 3 条 · 已保存 1 · 待核对 1 · 待补充 1` + 独立子卡列表；每张子卡 = 2.2 的完整卡 + 勾选框。
- 动作：逐卡核对/补全；`保存已选 2 条` 仅保存勾选且已核对的卡；已保存卡变只读回执。
- 规则：
  - 一张共同照片可被多张卡引用，但**群体描述不自动复制为每名幼儿的个体事实**；每张卡的事实区独立，需要教师分别写/改。 [C] 需求 §3.4
  - 单卡缺信息或失败不阻塞其他卡；`只处理未完成项` 出现在批次条旁。
  - 未勾选（未核对）的卡不得被“保存已选”带走。
- 状态：`部分完成` 是正常状态；批次完成条件 = 所有卡到达完成或明确放弃。
- 固定文案：`这一批里有一条还需要补充，其他已核对的可以先保存。`

### 2.4 补充问答卡（follow-up）

- 触发：服务端判定补充信息会影响发展线索/支持建议（`needs_input`），最多 2 轮。
- 组成：问题 + `为什么需要：…` + 教师补充输入（≥0 字）+ 此前补充记录（旧记录问题缺失时标注“历史补充（原追问问题未保存）”，不补造）。 [C] `review-client.tsx:794-878`、`follow-up.ts`
- 动作：`回答并继续` / `跳过，直接整理` / `不再追问`。 [C] `types.ts:6`
- 规则：追问只针对当前条目；同一批次其他条目的追问各自独立。
- 固定文案沿用现有：`Agent 只在补充内容会影响发展线索或支持建议时提问。原始观察保持不变。`

### 2.5 AI 草稿与教师修改/澄清卡

- 组成：领域（五大领域）、子领域、发展表现说明、发展亮点、支持建议、原文金句、教师备注；AI 标记；模型与整理时间。
- 动作：`重新生成` / `提交修改审核`（有教师修改时）/ `确认归档`（无修改时）。
- 修改审核状态：
  - `已理解这次修改，可以最终归档。` + 修改摘要 + 事实核对（有依据/部分有依据/依据不足）。
  - `需要澄清这次修改，再继续归档。` + 澄清问题 + 补充依据输入 + `提交澄清并重新审核` / `返回修改`。
- 规则：审核结果绑定当前内容快照；教师再改任何字段，旧审核失效并回到“提交修改审核”；澄清失败保留输入。 [C] `review-client.tsx:935-1176`、`teacher-edit-review.ts`
- 禁止：把“依据不足/需澄清”画成系统失败；静默覆盖教师修改。

### 2.6 指南决定卡

- 组成：表现条目文本 + 条目规则行（指南参考年龄、行为表现/保健参考、成人帮助策略）+ 依据来源（已归档观察 / 当前宿主观察）+ 逐字引用片段选择 + 决定选项。
- 决定文案（行为表现）：`已有相关线索` / `已确认观察到`；保健参考：`资料线索已核对` / `资料已核对`。 [C] `association-types.ts:211-219`
- 来源区分：`AI 建议` vs `教师手动关联`，正式程度上同等；`AI 关联待核对` 只是工作流状态，不是第四种正式状态。 [C] 需求；`association-types.ts:141-147`
- 状态：
  - 依据失效/目录版本变化：`有关联依据需要重新核对或移除`，不自动重放旧决定。 [C] `review-client.tsx:440-448、394-396`
  - 成人帮助：条目允许时说明帮助方式后仍可 `已确认观察到`；要求独立完成的条目只能 `已有相关线索`。 [C] `association-types.ts:231-237`
- 禁止：聊天自动点亮 ✓；把 AI 建议计入正式人数。

### 2.7 批准操作卡（统一批准形态）

- 适用：确认归档、指南决定写入、批量保存、管理员工具（建班/转班/建档/教师管理）。
- 组成：`将执行：<动作>` + `对象：<幼儿/班级/账号>` + `影响：<写入范围>` + 内容摘要 + 明确的主按钮（动词开头）。
- 规则：
  - 批准 = 本次动作 + 当前内容 + 当前对象；任一变化后旧批准失效（回“待核对”）。
  - 聊天不出现“模型已批准”；批准的可见文案来自服务端校验后的回执。
  - 高风险或不可逆动作（转班、重置密码、停用账号）沿用现有确认弹层语法（`AlertDialog`），不在聊天里直接执行。
  - 关闭聊天/切换会话不撤销已批准的写入。

### 2.8 真实回执卡

- 组成：结果行（`已确认归档` / `已保存` / `已更新`）+ 对象 + 时间 + 可核对引用（记录短 ID 或可打开链接）+ 分支结果。
- 分支必须分开表达：
  - `观察已确认，成长档案已更新`
  - `观察已确认，成长档案暂未更新，请稍后重试`（观察成功，档案失败） [C] `review-client.tsx:520-528`
  - `已确认归档，指南关联已写入`
  - `观察与关联决定已保存；证据详情暂时无法读取`（详情失败，不等于失败） [C] `review-client.tsx:497-507`
- 禁止：只有模型说“已完成”；回执没有服务端事实；把分支失败合并成“失败”。

### 2.9 待核对卡（结果不确定）

- 触发：网络中断、409、版本变化、响应无法证明生效、批量部分完成。
- 组成：事实说明（什么不确定）+ `重新读取核对` 按钮 + 不会自动重发的说明。
- 固定文案（沿用现有语义）：`归档结果待核对` / `不能据此认为未保存；可继续重试「重新读取」，不会自动重复提交归档。` [C] `review-client.tsx:736-756、304-306`
- 规则：确认已归档 → 转完成态；确认未归档 → 保留输入与选择，允许教师重试；仍读不到 → 保持待核对。
- 禁止：自动重试写请求；把待核对显示为成功或失败。

### 2.10 权限拒绝卡

- 按原因分型，不合并：
  - 未登录/会话失效（401）：`请先登录园所账号。` + `打开登录`（登录页/首页登录面板）。
  - 管理员教学动作（403 forbidden_role）：`管理员不能执行教学确认；可以查看或使用管理功能。`
  - 范围外（403 out_of_scope / not_found 语义不泄露）：`当前账号没有该业务资源的操作权限。`
  - 未分配班级（empty_scope）：`尚未分配任教班级，暂不能访问业务资料。` + `请联系园所管理员安排任教班级。`
  - 账号停用（403）：`账号已停用，请联系管理员。`
  - 身份服务不可用（503）：`身份服务暂时不可用，请稍后重试。`，fail closed，不展示任何园所数据。
- [C] 文案语义来自 `access.ts:39-43、140-156`、`new-observation-client.tsx:306-311`、AUTH 契约四态。
- 禁止：把权限拒绝说成“操作失败”；展示资源存在性；提供匿名继续入口。

### 2.11 安全凭据输入入口卡（密码不进入聊天/模型）

- 触发：用户请求涉及密码的动作（如“帮小满老师重置密码”“登录另一个账号”）。
- 组成：说明行 `密码不会出现在对话里，也不会发给 AI。` + 入口按钮 `打开安全设置窗口`（跳转现有安全页面：教师管理页 `/admin/teachers` 或登录页）。
- 行为：
  - 聊天只记录“已打开安全窗口”，不记录、不回显输入内容；窗口内输入与提交完全走现有页面/API 与 CSRF。 [C] `teacher-management.tsx:300、331（密码不展示、不保留、不写入浏览器存储）`
  - 操作后回执只写非敏感结果：`已提交密码重置；系统不会在对话中显示或保留密码。教师需用新密码重新登录。` 或不确定态：`重置结果待核对：教师名单无法证明密码是否已重置。请与教师核实，或明确再次重置。` [C] `teacher-management.tsx:244、252`
  - 若非管理员或未登录：先出权限拒绝卡。
- 禁止：聊天输入框内联密码字段；把密码/令牌/签名 URL 发给模型、写入消息、回执或日志；截图传播。 [C] 需求 §5

### 2.12 图片附件卡（素材/分析）

- 组成：缩略图条（每张 ≥44px 可点）+ 每张状态徽章 + `查看大图` + 来源标记。
- 单图状态机：`待上传 → 上传中 → 已上传 → 分析中 → 分析完成 / 分析失败`；另有 `已移除`。
- 动作：逐图 `重试`、`移除`；`这张图关联：<对象/记录>` 的选择；分析失败时 `继续用文字记录`。
- 规则：
  - 上传、分析、保存、归档各自独立反馈；分析完成不等于已保存。 [C] 需求 §3.4
  - 图片分析结果是“AI 解读”，与教师事实描述分栏显示，不得自动写进观察原文或确认稿。
  - 拍摄时间/人脸识别不自动成为观察日期/幼儿身份。 [C] 需求 §5
  - 临时签名 URL 不作为永久证据展示；显示时用对象引用与缩略图刷新。 [C] 需求 §4
- 固定文案：`这张图只作观察素材；分析结果不等于幼儿发展结论。`

## 3. 小芽姿态与文字（非语言状态的可读性）

头像 24–32px，平面小芽；姿态变化极轻（叶片角度/眼睛开合/小徽记），不依赖动画理解状态。

| 状态 | 姿态 | 必须出现的文字 | 出现位置 |
|---|---|---|---|
| 安静 | 小叶直立、闭眼 | 无（入口旁只有“芽芽”） | 入口 |
| 响应中 | 叶片前倾、注视点 | `正在想…`（流式开始后替换为正文） | 消息流 / 输入区 |
| 待确认 | 叶片举小旗/琥珀点 | 卡片状态徽章 + `请你核对` | 卡片 |
| 保存中 | 叶片环抱 | `正在保存…` | 按钮/卡片 |
| 成功 | 叶片舒展 + 绿点 | `已保存` / 回执文案 | 回执条 |
| 待核对/异常 | 叶片回卷 + 琥珀/玫红点 | `保存结果待核对` / 错误原因 | 卡片 |
| 权限受限 | 叶片挡在前 | 拒绝原因 + 下一步 | 权限卡 |

- `aria-live="polite"` 宣布状态切换（响应中开始/结束、回执）；重复弹幕不重复朗读。
- `prefers-reduced-motion`：所有姿态静止为静态图形，状态仍由文字与徽章表达。 [C] PRODUCT.md Accessibility
- 禁止：只用表情/动画表达保存成功；用连续弹跳吸引注意；把头像做成大插画。

## 4. 固定文案表（实现轮沿用，不逐字创造近义变体）

| 场景 | 文案 |
|---|---|
| 输入占位 | `问一个问题，或说“记一条小满的观察”…` |
| 原文不可改 | `观察原文（保存后不可修改，作为追溯依据）` |
| AI 标记 | `AI 生成，仅为草稿；确认后才进入正册` |
| 归档成功 | `已确认归档` |
| 待核对 | `保存结果待核对` |
| 无回执不成功 | `没有明确回执前不会显示“已保存”。` |
| 图片 | `这张图只作观察素材；分析结果不等于幼儿发展结论。` |
| 凭据 | `密码不会出现在对话里，也不会发给 AI。` |
| 关闭 | `关闭聊天不会撤销已完成的写入。` |

## 5. 无障碍与实现注意

- 卡片用语义结构（标题 + 列表 + 按钮），不用纯 `<div>` 堆叠；状态用文本 + `role="status"`。
- 对话框/抽屉使用现有 `Dialog`/`Sheet`/`AlertDialog`（焦点管理由组件提供）；关闭后焦点归还触发元素。
- 长卡片内部不做独立滚动区；键盘 `Tab` 顺序 = 标题 → 事实 → 核对 → 动作 → 回执。
- 只读态（管理员、撤权、历史受限）隐藏写按钮而不是置灰堆叠；同时保留原因文本。
