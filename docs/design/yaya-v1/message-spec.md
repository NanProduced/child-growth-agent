# 消息与卡片规格（问答、特殊消息、小芽姿态）— R1

本文件定义助手消息区的内容形态。三方向共用这些语义，差异只在承载方式（卡内/抽屉/分栏）。字段只描述“信息需求”，不冻结 DTO；DTO 归 YAYA0-CONTRACT。统一示例见 `synthetic-example.md`。

## 0. 服务分层（先分清“在回答”还是“在办理”）

| 层 | 触发 | 是否要求对象/原文 | 输出 | 写入 |
|---|---|---|---|---|
| 一般教育咨询 | 任意提问 | 否 | 文字回答（可长、可分段、可附公开来源） | 无 |
| 看图问答 / 作品分析 | 上传图片 + 提问；或点图问 | 否（不要求选幼儿、不要求 ≥10 字） | AI 解读 + 与事实分离的来源标注 | 无（除非教师显式说“记下来”） |
| 临时观察准备 | 明确“记一条…”“准备为观察” | 进入准备卡后按正式录入要求收集 | 准备卡（可编辑） | 仍不自动写库 |
| 已保存观察的正式整理 | 已有 observation ID | 已有 | 整理/追问/修改审核/指南/确认 | 沿用现有守门，不降低 |

仅提到幼儿（“刚才小满这样，怎么支持？”）→ 回答 + 可选 `准备为观察`，不自动变成录入流程。 [C] 需求 Q2/Q5；[R1]

## 1. 通用骨架

每张业务卡自上而下：

1. **标题行**：卡片类型 + 对象 + 时间/日期 + 状态徽章（附文字，不只用颜色）。
2. **事实区**：只放事实与来源；AI 生成段落带 `AI 生成` 标记；原文、教师补充、AI 解读来源分开。 [C] `status-badges.tsx:34-45`
3. **核对区**（可折叠）：对象/日期/事实对照/修改内容/附件关联/影响说明。
4. **动作区**：一个主按钮 + 次要按钮；点击后进入进行中并禁用重复提交。
5. **回执/状态条**：只有服务端回执到达才切完成态；否则按 §3.9 六类分型。

规则：

- 卡片有稳定对象绑定；页面切换、会话滚动、恢复历史都不改绑定。
- **批准完整性**：批准前必须能展开看到实际对象、关键事实、修改内容与附件关联；数量摘要（“亮点 2 条 / 建议 2 条”）只是折叠预览，不能替代核对内容。
- 任何“已完成”必须有回执内容（操作/记录引用、结果、时间），不能只有模型文本。 [C] 需求 §7
- 中文 IME：组合期间 `Enter` 不发送。

## 2. 问答与查询消息（不是表单壳）

### 2.1 一般教育回答

- 形态：正文可多段、可列表、可引用文号；超出约 6 行时给出“展开全文/收起”，不裁断。
- 来源：涉及权威依据时在回答底部列来源行（机构 + 文号/标题 + 日期 + 链接）；查不到就写“没有找到可引用的权威来源”，不编造。 [C] 需求 Q10；PRODUCT.md Web 查询约束
- 边界：不把幼儿个案数据发送给公开检索；不给出诊断、评分、排名。 [C] 需求 §5
- 可选动作：若回答中提到了某名幼儿，提供 `准备为观察`（显式点击才进入准备卡，不自动写入）。

### 2.2 看图问答 / 作品分析

- 触发：教师上传作品/活动图后直接问，或从图片卡点“问芽芽”。
- 形态：缩略图 + AI 解读段落（可长）+ `这只是图片解读，不是幼儿发展结论` + 可选 `准备为观察` / `仅保存图片到某条记录`。
- 规则：登录即可使用，不要求先选幼儿、不要求先填 ≥10 字原文；解读与教师事实、后续正式整理来源分开；图片不因分析自动关联任何记录。 [R1]

### 2.3 范围内查询结果

- 形态：回答 + 数据口径行（范围、期间、分母与否）+ 逐条来源可点开。
- 语义：区分 `没有记录`（0）/ `未获取`（null）/ `读取失败`；读取失败给重试，不显示 0。 [C] PRODUCT.md 首页契约口径；`children/[id]/page.tsx:176、212`
- 统计：不显示个体百分比/排名；班级占比必须带分母与期间。 [C] DESIGN.md 指南证据链约束

### 2.4 管理员查询与管理

- 管理员可问全园管理类问题与查询；管理动作（建班、任教分配、转班、建档基础信息、教师管理）出**管理操作卡**，走现有确认与权限。
- 管理员的教学动作（观察整理/确认、指南决定、成长/活动写入）不出可执行卡，直接给权限说明。 [C] `write-access.ts:33-40`、`access.ts:145-148`

### 2.5 未分配教师问答

- 可一般幼教问答；涉及园所私有资料的查询给 `尚未分配任教班级，暂不能访问业务资料。` + 联系管理员，不展示任何园所数据。 [C] `access.ts:40-43`

## 3. 特殊业务卡

### 3.1 多候选幼儿选择卡（仅真实歧义）

- 触发：**仅**真正重名、指代不清（“他们俩”“她”）、聊天上下文与页面对象映射不确定。
- **不触发**：一条输入明确描述多名幼儿的不同事实 → 直接生成独立卡（§3.3），不先强制选唯一幼儿。 [R1]
- 组成：候选列表（姓名 + 班级 + 学段；同名时出生年月差异）+ `都不是，重新说明`；点选后确认行 `对象：小满（中班·向日葵班）` + `[用它继续]`。
- 禁止：自动选第一个；把“可能相关”并入卡；静默替换已存在卡的对象；读取失败时假装没有候选。

### 3.2 观察准备卡（显式意图才进入）

- 触发：明确记录/操作意图（“记一条观察”“保存到小满的档案”“准备为观察”）。
- 组成：对象、日期（原生 date input）、情境（选填）、观察原文（白描提示；提交时才校验 ≥10 字）、图片缩略图、发生时班级核对区。
- 班级核对四态：`正在核对这条观察发生时的班级…` / `发生时班级：向日葵班（按分班历史核对）` / `无法自动确定，请选择当时所在班级` + 班级下拉（含已停用）+ 重试 / 失败 + `重新核对`。 [C] `new-observation-client.tsx:412-501`
- 动作：`保存观察并继续整理`（主）；`只保存原文`（次）。
- 规则：缺可选细节不追赶；保存前可自由看图问答，**但正式整理服务只在原文保存后启动**；原文保存后不可改写。 [R1]
- 固定文案沿用现有：`用白描方式记录幼儿的具体行为与语言。保存后原文不可修改`。

### 3.3 多人批次卡

- 触发：一条输入明确描述多个幼儿的不同行为（统一案例：小满、阿依）。
- 组成：批次条 `本批 2 条 · 已保存 1 · 待补充 1` + 独立子卡；每张子卡 = §3.2 的完整卡 + 勾选框。
- 规则：共同照片可被多张卡引用，但**不复制个体事实**；单卡缺信息/失败不阻塞其他卡；状态按 §3.9 分型；`只处理未完成项` 不等于把冲突或结果未知项重发。
- 固定文案：`这一批里有一条还需要补充，其他已核对的可以先保存。`

### 3.4 补充问答卡（follow-up）

- 触发：服务端判定补充会影响发展线索/支持建议（`needs_input`），最多 2 轮。
- 规则：
  - **不得重复追问原文已给出的信息**；只问真实缺失且会影响理解/支持的内容。 [R1]
  - 追问只针对当前条目；批次内各自独立。
  - 不承诺“跳过必然降级”或“回答必然确认”；决策仍由教师核对。
- 组成与文案沿用现有：问题 + `为什么需要：…` + 补充输入 + `[回答并继续] [跳过，直接整理] [不再追问]`。 [C] `review-client.tsx:794-878`

### 3.5 AI 草稿与教师修改/澄清卡

- 组成：领域、子领域、发展表现说明、发展亮点、支持建议、原文金句、教师备注；AI 标记；模型与整理时间。
- 动作：`重新生成` / `提交修改审核` / `确认归档`。
- 修改审核：`已理解这次修改，可以最终归档。`（含修改摘要、事实核对）或 `需要澄清这次修改，再继续归档。`（澄清问题 + `提交澄清并重新审核` / `返回修改`）。
- 规则：审核绑定当前内容快照；再改任何字段旧审核失效；澄清失败保留输入。 [C] `review-client.tsx:935-1176`、`teacher-edit-review.ts`

### 3.6 指南决定卡

- 组成：表现条目原文 + 条目规则行（指南参考年龄、行为表现/持续性/保健参考、成人帮助策略、是否计入行为统计）+ 依据来源 + 逐字引用片段 + 决定选项。
- 决定文案（行为表现）：`已有相关线索` / `已确认观察到`；保健参考：`资料线索已核对` / `资料已核对`。 [C] `association-types.ts:211-219`
- 规则（与 `src/lib/guide/decision-draft.ts` 一致）：
  - `adult_help: allowed`：说明帮助方式后，帮助下的充分证据仍可确认表现；**帮助本身不等于降级**。 [C] `types.ts:53-59`、`decision-draft.ts:123-124`
  - `adult_help: requires_independence`：有成人帮助时只能确认线索。 [C] `decision-draft.ts:126-128`
  - 持续性条目确认表现必须按持续表现处理。 [C] `decision-draft.ts:120-122`
  - AI 建议只是工作流状态；手动关联同等正式；陈旧决定必须重新核对或移除。 [C] `association-types.ts:141-147`、`review-client.tsx:440-448`

### 3.7 批准操作卡（完整内容）

- 适用：确认归档、指南决定写入、批量保存、管理操作。
- 组成：`将执行：<动作>` + `对象：<幼儿/班级/账号>` + `影响：<写入范围>` + **可展开的完整内容**：原文/关键事实/修改的具体字段与值/附件关联（缩略图与归属）；主按钮为动词。
- 规则：批准 = 本次动作 + 当前内容 + 当前对象；任一变化旧批准失效；高风险不可逆动作（转班、重置密码、停用）走现有 `AlertDialog` 确认，不在聊天直接执行。
- 禁止：用“2 条亮点”数量摘要代替可核对内容；模型生成 `approved:true` 放行。

### 3.8 真实回执卡

- 组成：结果行 + 对象 + 时间 + 可核对引用（操作/记录短 ID 或可打开链接）+ 分项结果。
- 分项示例：
  - `观察已确认，成长档案已更新`
  - `观察已确认，成长档案暂未更新，请稍后重试`
  - `已确认归档，指南关联已写入`
  - `观察与关联决定已保存；证据详情暂时无法读取`
- [C] 现有观察确认的分项语义 `review-client.tsx:497-528`；通用操作回执字段 [A] 依赖 CONTRACT-R1。

### 3.9 结果状态卡（六类分型，禁止一律叫“待核对”）

| 状态 | 含义 | 界面 | 允许动作 | 禁止 |
|---|---|---|---|---|
| 明确失败 | 已确认无提交效果 | `没有完成，输入还在` | `重试` | 显示为成功/部分成功 |
| 前提冲突 | 409/版本/归属变化 | `前提已变化，需要重新核对` | 读取新前提 → 重新核对 → 重新批准 | 沿用旧内容/旧批准 |
| 结果未知 | 网络中断/无法证明 | `保存结果未知，按原操作核对` | `重新读取核对`（只查原操作） | 因当前业务状态未变就判定失败；自动重发 |
| 执行中 | 原操作仍进行中 | `此操作仍在进行中` | 保留操作锁；其他无关条目照常 | 重复提交；把其他条目一起卡死 |
| 已保存详情暂不可读 | 业务已完成 | `已保存，详情暂不可读` | 只读重试详情 | 重新写；再次提交 |
| 批次分项 | 多条混合结果 | 逐项列出六类 | 只对“明确失败”项重试 | 把所有非成功项一起重发 |

[C] 状态语义参考现有 `confirmUnresolved`/`archiveCommitted`/`saved_detail_unavailable`；通用 operation 身份与回执查询 [A] 依赖 CONTRACT-R1，字段待统一。

### 3.10 身份与权限卡（按原因分型）

- 未登录/会话失效（401）：`请先登录园所账号。` + 登录入口。
- 撤权/转班但账号有效：可一般幼教问答；业务对象给出 403/范围说明，不渲染旧范围数据。
- 管理员教学动作（403）：`管理员不能执行教学确认；可以查看或使用管理功能。`
- 未分配班级：`尚未分配任教班级，暂不能访问业务资料。` + 请联系管理员。
- 账号停用（403）：`账号已停用，请联系管理员。`
- 身份服务不可用（503）：`身份服务暂时不可用，请稍后重试。` fail closed。
- **账号停用、会话失效、身份不可用：全部模型调用关闭（包括一般问答），不只隐藏教学按钮。** [R1]
- 禁止：把权限拒绝说成“操作失败”；泄露资源存在性。

### 3.11 安全凭据输入入口卡（密码不进入聊天/模型）

- 触发：涉及密码的动作（重置密码、登录另一账号）。
- 组成：`密码不会出现在对话里，也不会发给 AI。` + `打开安全设置窗口`（现有教师管理页/登录页）。
- 行为：聊天只记录“已打开安全窗口”；窗口内走现有页面/API 与 CSRF；回执只写非敏感结果（成功或“重置结果待核对：教师名单无法证明密码是否已重置”）。 [C] `teacher-management.tsx:244、252、300、331`
- 禁止：聊天内联密码字段；密码/令牌/签名 URL 进入消息、模型、回执或日志。

### 3.12 图片附件卡（上传/分析/保存/归档分开）

- 组成：缩略图条（≥44px）+ 每张状态徽章 + 大图查看 + 来源标记。
- 单图状态机：`待上传 → 上传中 → 已上传 → 分析中 → 分析完成 / 分析失败`；另有 `已移除`。
- 动作：逐图 `重试` / `移除`；`这张图关联：<对象/记录>`；分析失败时 `继续用文字记录`。
- 规则：分析完成 ≠ 已保存；AI 解读与教师事实分栏；拍摄时间/人脸不自动成为日期/身份；签名 URL 过期刷新缩略图。 [C] 需求 §3.4、§5
- 固定文案：`这张图只作观察素材；分析结果不等于幼儿发展结论。`

## 4. 小芽姿态与文字

头像 24–32px，平面小芽；姿态变化极轻，不依赖动画理解状态。

| 状态 | 姿态 | 必须出现的文字 | 出现位置 |
|---|---|---|---|
| 安静 | 小叶直立、闭眼 | 无（入口旁只有“芽芽”） | 入口 |
| 响应中 | 叶片前倾、注视点 | `正在想…`（流式开始后替换为正文） | 消息流 / 输入区 |
| 待核对 | 叶片举小旗/琥珀点 | 卡片状态徽章 + `请你核对` | 卡片 |
| 保存中 | 叶片环抱 | `正在保存…` | 按钮/卡片 |
| 成功 | 叶片舒展 + 绿点 | `已保存` / 回执文案 | 回执条 |
| 结果未知/异常 | 叶片回卷 + 琥珀/玫红点 | 六类状态文案（§3.9） | 状态卡 |
| 权限受限 | 叶片挡在前 | 拒绝原因 + 下一步 | 权限卡 |

- 姿态只服务工具/进度；普通回答不要求小芽长文，正文可长。
- `aria-live="polite"` 宣布状态切换；重复弹幕不重复朗读。
- `prefers-reduced-motion`：姿态静止，状态仍由文字与徽章表达。 [C] PRODUCT.md Accessibility

## 6. 无障碍与层语义

- 语义结构（标题 + 列表 + 按钮），状态文本 + `role="status"`。
- **层语义**：桌面侧栏是**非模态**区域（背景页面仍可滚动/点击，无焦点陷阱，`Escape` 关闭，焦点归还入口）；核对抽屉/确认对话框是**模态**（焦点陷阱，关闭归还触发元素）；手机全屏是页面级导航（返回键/返回按钮），不是默认 Sheet 翻版。实现时不得用默认 `Sheet` 的模态行为冒充“边看边聊”，也不得让非模态侧栏抢走页面焦点。
- 长卡片内部不做独立滚动区；键盘 `Tab` 顺序 = 标题 → 事实 → 核对 → 动作 → 状态。
- 只读态隐藏写按钮并保留原因文本。
