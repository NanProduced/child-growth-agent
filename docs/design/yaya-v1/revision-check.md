## B 恢复路径不扩大重复提交

- 六类分型：明确失败 / 前提冲突 / 结果未知 / 执行中 / 已保存详情暂不可读 / 批次分项（`recovery-spec.md` §1、`message-spec.md` §3.9）。通过。
- 结果未知只按原操作核对；“当前业务状态未变 ≠ 请求失败”写明（§1.3）。通过。
- 执行中保留操作锁、其他条目可继续（§1.4）。通过。
- 批次“只处理未完成项 ≠ 重发所有非成功项”（§1.6、S9）。通过。
- 证据范围修正：现有 `reconcileConfirmResult` 只读观察状态，不是通用 operation 回执账本；通用字段标 [A] 依赖 CONTRACT-R1（`recovery-spec.md` §0、`flow-analysis.md` S8/证据台账）。通过。
- 正反流程表 8 条（原请求未结束读到未归档 / 回执缺项 / 另一端不同内容 / 审批后改字段 / 恢复旧批准 / 批次 / 撤权 / 停用）（§2）。通过。
- 审批后修改字段 → 旧批准失效（`message-spec.md` §3.7）。通过。

## C 身份状态与私有历史

- 撤权/转班但账号有效 → 可一般问答（`flow-analysis.md` S11、`recovery-spec.md` §1.7、`message-spec.md` §3.10）。通过。
- 账号停用/会话失效/身份不可用 → **全部模型调用关闭**（含一般问答）；三处口径一致。通过。
- 同账号范围变化 → 重新投影业务来源；换账号 → 立即清空草稿/图片/消息/待提交选择、不闪现（§1.7、S11）。通过。
- 恢复不自动执行写入；tool part 取消不丢草稿；显式继续需当前身份 + 最新前提 + 新批准（`recovery-spec.md` §1.9、`same-record-flow.md` §6、`brief.md` §5）。通过。
- 后台已保存/执行中的操作不因关闭侧栏或停止模型显示成已撤销（§1.9、`brief.md` §2.2）。通过。

## E 问答、布局与不丢输入

- 长文规则：短文本仅限进度/工具摘要；回答可多段并可展开来源（`direction-options.md` 共同条 10、`message-spec.md` §2.1、`future-acceptance.md`）。通过。
- 补问答呈现：一般咨询/看图问答/范围内查询/公开来源/管理员查询与管理/未分配问答（`message-spec.md` §2.1–2.5）。通过。
- B 抽屉关闭保留未提交编辑，明确“放弃修改”才清理；批准仍需最新内容（`direction-options.md` B.1、`recovery-spec.md` §1.9）。通过。
- A 统一：卡内按钮 + 输入区吸底（README 表、A.6、prompt 02），不再同时给“吸底操作条”。通过。
- C 分栏条件：仅宽工作区分栏；360–460px 侧栏单列 + 覆盖面板；批量进独立工作区（C 引言、C.1）。通过。
- 手机输入：原生 `100dvh` + 安全区优先，`visualViewport` 仅补偿且不双重抬升；核对表单/抽屉同样处理键盘（`brief.md` §2.4、B.6、`future-acceptance.md` §1）。通过。
- 层语义：侧栏非模态（背景可操作、无焦点陷阱）、抽屉/对话框模态、手机全屏为页面级（`brief.md` §2.2、`message-spec.md` §6、`future-acceptance.md` §3）。通过。
- 批准完整性：实际对象、关键事实、修改内容、附件关联可展开；数量摘要不替代（共同条 3、§3.7、future-acceptance）。通过。
