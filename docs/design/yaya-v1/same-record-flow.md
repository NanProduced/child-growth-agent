# 同一记录：表单 → 图片 → Review → 聊天接续 → 档案回看

核心不变量：**一条观察只有一个记录 ID、一份原文、一份确认稿**。表单页、Review 页、聊天卡、成长档案附件都是这份记录的投影，不新建“聊天档案”，不复制记录，不重复上传。

## 1. 单记录身份

| 环节 | 载体 | 规则 |
|---|---|---|
| 表单 / 聊天准备卡 | 服务端保存后的 observation ID | 保存前是本地准备内容（图片问答、看图分析可独立存在，不构成记录）；保存动作只有一个（服务端 POST），成功后返回 ID。 [C] `src/app/api/observations/route.ts:116-125`；[R1] |
| Review 页 | `/observations/{id}/review` | 只读服务端状态；教师修改在确认时提交。 [C] `review-client.tsx` |
| 聊天接续卡 | 同一 observation ID | 聊天消息与卡片带 `record` 引用；同一 ID 不重复建卡。 |
| 成长档案 | `children/{id}` 时间线 | 只展示同一记录；已确认显示确认稿与附件。 [C] `children/[id]/page.tsx:398-485` |
| 档案附件（图片） | 媒体对象 ID + 引用 | 同一媒体对象可被多条记录引用；上传一次。 [A] 引用模型归 MEDIA1 |

## 2. 主链路（示意）

```
① 表单页录入 ───────────────┐
② 聊天内“记一条观察” ──────┤──▶ 服务端保存原文 ──▶ observation ID
③ 首页/档案“记录一次观察” ──┘         │
                                      ▼
                        AI 整理（可选）→ 追问（按需）
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
              Review 页核对                        聊天接续卡核对
             （原文+草稿+指南）                  （同一 ID、同一状态）
                    └─────────────┬─────────────────────┘
                                  ▼
                     教师批准（内容+对象绑定）
                                  ▼
                  服务端执行：确认归档 / 指南决定写入 / 档案更新
                                  ▼
                        真实回执（分项）→ 成长档案回看
```

- 从 Review 页打开聊天：上下文条显示 `正在看：小满 10月8日 观察草稿`，聊天**聚焦已存在的接续卡**（按 observation ID 去重），不新建卡、不要求重复粘贴原文。 [A] 去重键与投影归 UI1/DATA1
- 从聊天保存后进入 Review：跳转同一记录；Review 的“重新生成/修改审核/归档”等动作与聊天卡共享服务端事实，任一侧写入后另一侧通过重新读取更新（现有 `serverStamp`/`router.refresh` 模式）。 [C] `review-client.tsx:231-290`

## 3. 图片：一次上传，处处引用

1. **选择**：表单页附图、Review 页附图、聊天附图三个入口共用同一上传控件与会话（`brief.md` §2.5）。
2. **上传**：只上传一次，得到媒体对象引用；缩略图在任何界面都来自同一引用。
3. **分析**：分析是媒体对象的属性/派生结果，不是第二份记录；分析结果标注 `AI 解读`，与教师事实描述来源分开，**不自动写入 raw_text 或确认稿**。
4. **关联**：一张共同照片可被多条记录引用（一次选择、多卡勾选），但事实描述不复制。 [C] 需求 §3.4
5. **保存/归档**：图片随记录保存；归档后档案回看显示同一引用；签名 URL 过期用缩略图刷新，不把临时 URL 当永久证据。 [C] 需求 §4

失败交换：缺可选细节（情境、备注）不阻塞保存；分析失败可继续文字；图片失败不阻塞已核对的文字记录。 [C] 需求 §3

## 4. 四层反馈分离（所有入口一致）

| 层 | 状态 | 呈现 |
|---|---|---|
| 上传 | 待上传/上传中/已上传/失败 | 缩略图徽章 + 重试 |
| 分析 | 未分析/分析中/完成/失败 | 图片卡状态行；失败可继续文字 |
| 保存 | 待保存/保存中/已保存/明确失败/冲突/结果未知/执行中 | 卡片动作按钮 → 回执/六类状态（`recovery-spec.md`） |
| 归档 | 待确认/确认中/已归档/档案更新失败/详情暂不可读 | 回执分项（见 `message-spec.md` §3.8） |

- 上传成功不显示“已保存”；分析完成不显示“已归档”；归档成功但档案更新失败时，观察仍是成功、档案分支单独提示。 [C] `review-client.tsx:520-528`

## 5. 与现有正式守门的关系（不降低）

- `raw_text` 保存后不可改写；聊天不提供编辑原文。 [C] `types.ts`、`review-client.tsx:686-693`
- AI 草稿必须经教师确认；聊天卡上的“确认归档”与服务端确认是同一件事，没有聊天特权。
- 教师修改必须经过修改审核；指南决定必须逐条给依据与引用；聊天不能自动点 ✓。 [C] `review-client.tsx:935-1176`、`association-types.ts`
- 管理员/未分配/未登录在聊天里的能力与页面一致（只读或仅问答）。 [C] `write-access.ts`、`access.ts`
