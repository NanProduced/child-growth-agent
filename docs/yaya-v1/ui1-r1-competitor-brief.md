# YAYA-UI1-R1 竞品取舍（有界公开研究）

研究日期：2026-10-07（Asia/Shanghai）。只访问公开入口/帮助页，未登录私人账号、未读取私人历史、未发送幼儿资料。

## 观察边界

- ChatGPT 公开入口可看到侧栏搜索/新建会话、输入区、文件/图片入口和 Web search；登录后能力与历史内容未观察。
- Gemini 公开入口停在 Sign in；登录后网页对话、工具过程、历史与移动端状态均为 NOT_OBSERVED。
- 豆包公开 /chat/ 与 thread list 的动态内容不可稳定读取；公开分享页只观察到文件拖放/单文件提示，登录后聊天、历史与停止语义为 NOT_OBSERVED。
- 豆包官方帮助/规则只用于确认公开能力边界：对话历史可删除，上传内容与云盘是账号私有范围；不把帮助页当成实际 UI 截图。

## 证据 → 场景 → 芽芽采用 → 不采用

| 证据 | 适用场景 | 芽芽采用方式 | 不采用理由 |
|---|---|---|---|
| ChatGPT 公开入口显示“新会话 + 输入框 + 图片/文件 + Web search”，但登录后工作区未观察 | 首次进入、开始普通咨询 | 空态直接给一个输入区；附件/上下文贴近输入；工具只显示一行摘要并保留来源入口 | 不复制模型选择、语音、图片生成、Deep research 等未实现功能 |
| ChatGPT 公开入口显示侧栏搜索会话；登录后历史正文未观察 | 历史导航、回到当前会话 | 默认桌面侧栏、手机全屏；历史切换与当前会话分开；历史只读恢复不自动执行 | 不把通用“聊天历史”当成业务批准/执行账本 |
| 豆包公开分享页观察到文件拖放和“最多 1 个文件”；官方云盘说明上传内容归账号云盘，历史/删除另有入口 | 附件与资料回看 | 单图单请求、失败可重试、同槽位复用上传身份；超 8 张明确提示；授权来源/元数据状态分开 | 不照搬云盘/分享/公开文件能力；本轮不增加真实桶或公开分享 |
| Gemini 公开入口仅显示 Sign in；官方帮助确认移动端/多语言范围，网页登录后流程未观察 | 移动端、权限与首次进入 | 未登录/401/403/503 明确说明并关闭模型；手机用 dvh/安全区/≥44px 控件 | 不凭记忆补造 Gemini 的后登录行为，不引入语音/视频入口 |
| 三家公开资料都不能证明“工具进行中”与业务写入终态的同一语义 | 查询、保存、取消、恢复 | 查询先摘要；终态由真实协议状态驱动；未知只读原 operation/run，保留操作锁 | 不展示原始 JSON、内部异常、模型隐式推理或假“已保存” |

结论：芽芽借鉴的是“直接开始、输入区承载附件、历史可回到当前会话、工具过程渐进披露”这些已观察到的交互骨架；批准内容、来源依赖、未知回执和正式归档仍以本项目冻结契约为准。
