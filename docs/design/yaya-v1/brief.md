# 芽芽助手 v1 设计 brief（yaya-v1）

本文件是固定约束与壳层规格。方向差异见 `direction-options.md`；卡片与失败细节见 `message-spec.md`、`recovery-spec.md`。

## 1. 固定业务约束（不重问，不扩展）

以下来自已确认的 11 项选择与批准需求全文，设计不得改变：

1. 仅登录园所账号可用，包括一般教育问答；能力与当前角色/范围一致。管理员不能执行教学确认；未分配班级教师可一般问答，不读园所私有资料；未登录不开放模型。 **[C] `src/lib/accounts/access.ts:31-45`、`src/lib/guide/write-access.ts:33-40`**
2. 桌面右下角小芽入口打开右侧聊天栏，可进入独立工作区；同一会话。参考 Notion 的入口与操作习惯，不照抄其整页。
3. 对话灵活、不绑定幼儿；普通教育问题直接答，不强制选幼儿。结合明确指令与上下文识别对象，歧义再问。**页面切换不得静默改变待确认卡的对象与内容。**
4. 首版文字 + 图片（选图/拍照）；图片分析与表单/Review/档案附件共用同一能力，不做录音/视频。
5. 多人输入拆独立记录卡，逐人核对后勾选保存，结果逐项展示；单条疑问不阻塞其余条目。
6. 默认账号私有历史、跨设备继续；支持新建/查看/继续/删除。恢复不自动重做写入；历史不绕过当前权限。
7. 小芽为简洁绿色拟人角色，少量真实状态姿态 + 文字进度；不做 3D、养成、满屏贴纸或大插画。
8. 现有操作页保持“轻量成长观察册”，shadcn/UI 语法与现有组件优先；**首页 token（`home-*`）不推广到助手或任何其他页面**。 **[C] DESIGN.md 首页局部范围规则**

## 2. 壳层规格（所有方向共用）

### 2.1 桌面入口（≥1024px）

- 固定右下角，距视口右边与底边各 24px（安全区存在时叠加 `env(safe-area-inset-*)`）；触控/点击目标 ≥44×44px。
- 静止时只有小芽头像 + 极短标签「芽芽」；不显示未读数字、不合并任何待办计数。
- 旁路状态（可用文字或 `aria-live`）：响应中、有一条待确认、保存中、异常。不得只靠颜色或动画表达。 **[C] PRODUCT.md 状态不只靠颜色**
- 不得遮挡首页唯一主行动与其他页主按钮；窄于 1024px 时打开为全屏（见 2.4）。

### 2.2 右侧聊天栏（1024–1439px 与 1440px+）

- 从右侧滑入，宽 `clamp(360px, 30vw, 460px)`，覆盖在页面之上（不推挤布局），顶部对齐正文区，底部贴底。
- 面板 = 头部（小芽 + 会话标题 + 历史/新建/关闭）→ 消息区 → 输入区。
- `Escape` 关闭；关闭后焦点回到小芽入口。面板打开不改变页面当前滚动位置与表单未保存输入。
- 面板与工作区是同一个会话、同一份账号私有历史。

### 2.3 独立工作区（≥1024px）

- 从面板头部「在工作区打开」进入；同一会话、同一消息流，不复制、不另存。
- 工作区是路由级页面（实现建议 `/assistant`，归 UI1，本轮不建 mock 路由）；左侧会话与历史，中央消息区（最大阅读宽约 720px）。
- 从具体页面进入时显示可解除的上下文条（见 2.5）；工作区可另开新对话。

### 2.4 手机 390 全屏

- 小芽入口为右下浮动按钮；打开即全屏会话页，不做窄面板。
- 全屏页 = 头部（返回/关闭 + 标题 + 历史入口 + 新建）→ 消息区 → 输入区。
- **软键盘**：输入区随 `visualViewport` 抬升，消息区底部留出键盘高度，输入框与发送按钮始终可见；不依赖 `100vh`（用 `100dvh` 或脚本读取可视高度）。
- **安全区**：输入区与浮动入口加 `env(safe-area-inset-bottom)`；头部加 `env(safe-area-inset-top)`。
- **关闭/返回**：系统返回键与返回按钮等效；关闭回到进入前的页面与滚动位置；有未发送文字或未完成核对时，关闭前轻提示（不强制、不丢字）。
- **焦点**：打开后焦点进入消息区/输入框；抽屉或全屏核对层内焦点环捕获，关闭后归还触发元素。
- **长卡片**：单卡可超一屏；卡片内不嵌套滚动，整页纵向滚动；卡片操作按钮在卡内重复出现（不复用桌面吸附条）。
- 核心触控目标 ≥44px；不做横向滚动。

### 2.5 来源与对象选择（输入区，所有方向共用）

输入区结构（自上而下）：附件缩略图条 → 上下文 chips 行 → 文本输入 → 发送。

- **对象 chip**：`对象：小满`。未选则不显示，聊天保持灵活；选择后仅作用于本条消息的“待确认卡”，不全局过滤历史。
- **来源 chip**：`来源：观察草稿` / `来源：成长档案` / `来源：指南条目` / `来源：公开资料`。来自 Review 或档案页打开时自动带上一次，用户可解除；**自动带上是上下文提示，不是批准**。
- 页面切换时：只更新入口旁的轻提示（“你正在看小满的档案”），**不静默改写任何已存在卡片的对象/内容/日期**；要切换对象必须在卡内显式操作（“改用…/换对象”）。
- 歧义对象（重名、指代不明、多幼儿混在一条输入）：不猜，先出「多候选幼儿选择卡」（`message-spec.md` §2.1）。
- 输入法：中文 IME 组合期间 `Enter` 不发送（检查 `compositionstart/end` 或 `isComposing`）；发送快捷提示写在占位文案里。

## 3. 视觉与组件口径

- 复用 shadcn/UI 现有原语：`Button`、`Card`、`Sheet`、`Drawer`、`ScrollArea`、`Tabs`、`Alert`、`Badge`、`Checkbox`、`Textarea`、`Select`、`Separator`、`Tooltip`、`AlertDialog`。 **[C] `src/components/ui/**`**
- 沿用当前全局 OKLCH 主题与中文无衬线栈；助手不引入新色板、不使用首页 `home-*` token。 **[C] DESIGN.md 首页范围规则**
- 小芽头像为小尺寸（24–32px）平面图形；消息正文以文字与卡片为主，人物不进入信息结构。
- 状态色参考现有语义：草稿/待判断=天蓝，待补充=玫红，待确认=琥珀，已归档=绿，AI=紫；并始终附文字标签。 **[C] `src/components/status-badges.tsx`**
- 动画克制：状态切换允许淡入/轻位移；`prefers-reduced-motion` 下全部停用，状态由文字与图形姿态表达。 **[A] 具体动效在实现轮定义**

## 4. 非目标

- 不做聊天版专属“第二档案”：表单、Review、聊天、档案附件共享同一业务事实与同一记录 ID（`same-record-flow.md`）。
- 不新增评分、排名、诊断、个人完成率；聊天不点指南 ✓，不把未确认内容混入正式证据。 **[C] PRODUCT.md Durable constraints**
- 不做录音/实时语音/语音播报/视频分析。
- 不做家长端、分享、公开注册、角色切换器。
- 不发明“聊天内写数据库”的能力；模型不能通过自生成 `approved:true` 放行。 **[C] 需求全文 §3.5、§5**
- 不把合成示例当真实业务验收；示例全部标注合成（`synthetic-example.md`）。

## 5. 依赖与停止点

- 卡片字段依赖 `YAYA0-CONTRACT` 的 DTO 与工具覆盖表；本设计以“信息需求”描述，不冻结字段名。
- 具体 runtime（LocalRuntime vs ExternalStore）依赖 `YAYA-TECH0`；本设计只给形态要求：单会话流、附件、历史投影、无第二状态源。
- 用户选方向前，不进入 `YAYA-UI1`，不改任何产品 UI。
