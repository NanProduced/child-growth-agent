# 芽芽观察全局页面 Critique

## 目标与范围

审查目标：整个 `src/app` 页面体系与核心教师任务流。
模式：Operate；用户是幼儿园教师，核心目标是从真实观察快速进入记录、确认和后续支持。
视觉目标：轻量成长观察册，而非 SaaS 控制台。

## Design specificity verdict

视觉语言已有芽芽观察自己的识别度：暖白画布、芽叶绿、合成数据提示、幼儿观察语境和证据导向文案都不是通用后台默认值。问题在于页面结构仍主要由“导航 + 多块卡片 + 列表”拼接而成，班级、儿童、观察、成长小结和活动支持仍像并列模块。它有品牌皮肤，但还没有形成与教师工作顺序绑定的产品骨架。

## Cognitive load

失败项：5/8，整体为高认知负担边缘。

- Single focus：工作台同时展示开始记录、建立档案、班级 chips、最近观察、待处理、成长档案，主任务不够集中。
- Chunking：页面大体有分区，但列表、状态、摘要和操作经常在同一屏并列出现。
- Grouping：班级/儿童/观察关系在单页内可以理解，跨页面时缺少持续上下文。
- Visual hierarchy：卡片都有相近的视觉重量，用户不容易判断“现在最该做什么”。
- One thing at a time：观察 Review 同时承载原文、流程、AI 草稿、修改、Agent 审核和确认。
- Minimal choices：导航和班级筛选尚可，但首次进入的入口选择超过一个。
- Working memory：用户需要记住当前班级、儿童、观察状态后再进入下一个页面。
- Progressive disclosure：活动、报告、档案、班级的复杂度主要靠跳转展开，而不是由任务阶段逐步揭示。

## Emotional journey

开场是温和的，合成数据和视觉也能降低压力；但首次使用的情绪低谷出现在“我应该先建班级、先建档，还是直接开始记录？”这一刻。Review 页面又出现第二个低谷：教师需要在长页面中判断 AI 草稿、修改、审核和确认的关系。确认成功是高点，但之后回到成长档案时，没有统一的“下一步支持 / 再记录一次”收束动作。

## Strengths

1. 原始观察、AI 草稿、教师确认稿的层级是真实产品价值，Review 页有明确证据基础。
2. 班级学段、转班历史和发生时班级已经进入产品上下文，不再只是儿童卡片上的文字标签。
3. 空状态、合成数据、教师门禁和窄屏布局已有基础，视觉语气温和，没有滑向评分或游戏化。

## Priority issues

### [P1] 没有任务型首次进入路径

工作台把“开始记录”“建立成长档案”“班级筛选”“最近观察”“待确认”“成长档案”同时铺开。新教师必须自行推导正确顺序，产品没有把第一次成功体验设计成一条路。

Fix：增加 context-aware onboarding。无数据时只引导“建立班级 → 建立成长档案 → 记录第一次观察”；有班级但无儿童时进入建档；有待确认时优先进入 Review；已有数据时显示“继续处理”而不是重复展示所有入口。支持跳过，但保留入口。
Suggested command: `$impeccable onboard` + `$impeccable shape`。

### [P1] 信息架构是模块导航，不是教师任务导航

班级、成长档案、观察记录、活动支持和成长回顾在导航中平行出现，但教师的真实任务是围绕一个班级或一个儿童连续完成动作。当前页面可以互相跳转，却没有持续的“当前上下文”。

Fix：重构为“当前工作上下文 + 下一步动作”：顶部保留轻量全局入口，页面内固定显示当前班级/儿童；从班级进入儿童，从儿童进入观察和支持，回顾页回到同一对象，而不是回到泛列表。
Suggested command: `$impeccable shape` + `$impeccable layout`。

### [P1] 工作台和列表页功能平铺，缺少优先级

工作台、活动支持、成长回顾都使用相似卡片网格或列表，已确认、待处理、无记录、生成活动支持等状态通过标签表达，但没有统一的优先级规则。用户看到的是“很多内容”，不是“现在最值得做的一件事”。

Fix：工作台首屏只保留一个主行动、一个待处理区和一个最近记录区；把班级筛选降为上下文选择器；把成长档案/活动支持作为由当前对象进入的后续动作。
Suggested command: `$impeccable distill` + `$impeccable layout`。

### [P1] 建档与第一次观察没有形成连续 onboarding

建档向导本身有三步，但完成后只是跳到观察录入；首次教师仍需重新理解“为什么要记录原文、什么时候会追问、什么时候确认”。观察录入页也没有明确说明它是建档后的下一步。

Fix：把建档后的跳转设计成“第一次观察”连续任务，显示当前儿童和班级上下文；在观察录入前用一条短说明讲清“先记录事实，AI 只生成草稿，最后由教师确认”。将可选补充信息继续后置，不要在首次进入时一次性解释所有能力。
Suggested command: `$impeccable onboard` + `$impeccable clarify`。

### [P1] Review 页面承载过多决策，确认动作不够突出

Review 同时放置原文、进度条、追问、AI 草稿、字段编辑、Agent 修改审核和确认。信息层级虽然有颜色区分，但教师仍需要在长页面中完成多次判断；真正的“下一步”没有稳定地占据视觉焦点。

Fix：采用“证据 → 理解 → 确认”的分段流程；默认先读原文和 AI 摘要，字段编辑与审核细节折叠；底部提供固定的当前主行动（回答追问 / 提交修改审核 / 确认归档）。确认后直接给出“查看成长档案 / 继续记录”二选一。
Suggested command: `$impeccable distill` + `$impeccable harden`。

### [P2] 活动支持和成长回顾仍然是结果页，不是下一步任务

活动支持页能找到儿童，但用户仍需跳回成长档案生成建议；成长回顾能读内容，但缺少“基于这段回顾接下来做什么”的动作闭环。对于演示，这会削弱“观察 → 支持”的叙事。

Fix：保留活动支持和成长回顾作为对象内的后续阶段；独立页面只做索引，不重复承载生成流程。每个结果页统一提供一个下一步：记录一次新观察或生成/查看活动支持。
Suggested command: `$impeccable shape` + `$impeccable clarify`。

## Persona red flags

### Jordan（首次使用教师）

- 进入工作台后会看到多个同等重量入口，不知道是否必须先建班级。
- 看到“AI 整理”“Agent”“成长档案”等概念，但缺少一句完整流程说明。
- 完成建档后进入观察录入，缺少“你现在正在做第几步”的连续感。

### Sam（键盘/辅助技术用户）

- 视觉结构主要依赖卡片和颜色层级；需要确认所有状态标签、筛选 chips 和折叠详情的读屏顺序。
- Review 页面较长，若标题层级和当前主行动没有形成清晰的 heading/focus 顺序，键盘浏览成本会明显增加。
- detector 没有发现静态 primary findings，但这不能替代真实键盘和读屏验收。

### Casey（窄屏、被打断的教师）

- 录入页和 Review 页仍需要较长滚动；被打断后缺少“继续未完成记录”的明显入口。
- 顶部导航收缩后仍需要回到页面上方寻找上下文和主要动作。
- 活动支持生成属于慢操作，loading 有了，但页面没有让用户明确知道生成发生在哪个儿童、使用了哪些已确认观察。

## Minor observations

- 顶部导航已经比旧版轻，但“班级 / 成长档案 / 观察记录 / 更多”仍是对象/证据/输出的混合层级。
- “活动支持”页和“成长回顾”页当前可用，但作为独立入口会放大模块感；更适合作为儿童/班级上下文下的二级视图。
- 建档表单中学段和班级的两级选择是正确方向，但视觉上仍像普通后台表单，缺少对“为什么现在需要这一步”的情境说明。
- 工作台中的合成数据说明位置偏后，首次进入时可以更早说明这是演示环境，但不要增加额外横幅。
- 视觉 detector 本轮返回空结果；这说明没有静态反模式命中，不代表信息架构和任务流已经合理。

## Questions to consider

1. 如果教师第一次打开产品，是否应该只看到一个“开始建立班级并记录第一条观察”的主路径，而不是完整模块导航？
2. “班级、儿童、观察”是否应该成为持续可见的三级上下文，而不是三个并列页面？
3. Review 页面是否应该优先服务“完成一次确认”，把 AI 细节和证据追溯放到确认动作之后展开？
