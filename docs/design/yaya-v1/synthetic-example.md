# 合成示例：两个幼儿、一张共同照片、一条待补充卡

> **来源声明（必须随稿展示）**：本示例为设计沟通用**合成场景**。园所“星芽幼儿园”、班级“向日葵班（中班）”、幼儿“小满”“阿依”均为**化名**，照片为**合成示意图**（不出现真实幼儿面孔），所有时间、观察与指南条目引用为设计构造，**不是真实园所数据，也不是教师实测**。示例中所有业务状态与文案来自本目录规格与基线代码语义，不来自真实业务验收。

## 1. 场景与输入

- 时间：合成“2026-10-08 上午区域活动（积木区）”。
- 教师原始输入（白描，合成）：
  > “积木区，小满自己搭了一座长桥，中间塌了三次，他换了更宽的底座，第四次搭稳了，喊我看。阿依一直在旁边看，我提示她‘要不要问问小满怎么搭的’，她才走过去问，小满教了她一块，两个人一起又搭了一段。”
- 输入不绑定幼儿 → 芽芽出**多候选选择/批次拆分**：识别出两个不同事实主体 → 生成两张独立卡，不把两个人的事写成一段群体描述。

## 2. 两张独立卡（同一事件，不同事实与帮助条件）

| 项目 | 小满卡 | 阿依卡 |
|---|---|---|
| 对象 | 小满（中班·向日葵班） **[合成]** | 阿依（中班·向日葵班） **[合成]** |
| 事实（教师白描，各自独立） | 独立搭建长桥，塌三次后换宽底座成功，主动展示 | 先旁观，在成人提示下主动询问并加入同伴搭建 |
| 图片 | 共同照片（积木区全景） | 共同照片（同一媒体对象，另一条引用） |
| 帮助条件 | **独立完成**（无成人帮助） | **有成人帮助**：教师口头提示“要不要问问小满怎么搭的” |
| 指南条目（合成引用） | 科学·形状与空间：能用自己的方式解决搭建中的问题 | 社会·人际交往：愿意与同伴一起游戏 |
| 条目成人帮助规则 | 要求独立完成 | 允许成人帮助，需说明帮助方式 |
| 可能的决定 | `已确认观察到` | 事实有成人提示，但条目**要求独立完成** → `已有相关线索` |

- 共同照片旁始终标注：`这张图只作观察素材；分析结果不等于幼儿发展结论。`
- 两张卡分别核对、分别保存；**不把“小满的做法”复制进阿依的事实**。

## 3. 一条待补充卡（阿依 · 第 1/2 轮）

> 芽芽：阿依加入游戏前，老师具体是怎么提示的？这会帮助判断她是主动交往还是需要较多帮助。
> 为什么需要：成人帮助方式会影响该条目是“已确认观察到”还是“已有相关线索”。
> 教师补充：略（可跳过）
> `[回答并继续] [跳过，直接整理] [不再追问]`

- 小满卡不受这条追问影响：小满可先核对、先保存。
- 教师回答后草稿更新；若跳过，按现有信息整理，并在决定时如实降为线索。

## 4. 批次与逐项回执（合成）

```
本批 2 条 · 已保存 1 · 待补充 1
☑ 小满卡（已核对）
   → 已确认归档 · 14:32 · 观察 #a1c1…；成长档案已更新；指南关联已写入（已确认观察到）
☐ 阿依卡（待补充：成人帮助方式）
   → [补一句]  （不阻塞小满）
```

- 若保存小满卡时网络中断：只有小满卡变 `保存结果待核对`，阿依卡与已核对选择仍在；`重新读取核对` 后按服务端事实继续。 [C] `recovery-spec.md` §1.2
- 若阿依卡在保存时发现条目依赖的观察版本已变化：该卡要求 `重新核对或移除`，小满卡的回执不受影响。 [C] `review-client.tsx:440-448`

## 5. 档案回看（合成）

- 成长档案时间线显示：小满 2026-10-08（已确认归档，科学，含共同照片引用）；阿依同日（待补充/后续确认）。
- 成长小结只引用已确认观察；阿依未确认前不进入小结依据。 [C] `children/[id]/page.tsx:232-245`

## 6. 示例要证明与不要证明的事

**要证明**：多幼儿不串档、共同照片一次上传多处引用、成人帮助规则影响决定、单条待补充不阻塞其余、回执逐项。

**不要证明**：不证明聊天已实现、不证明图片能力已实现、不证明交互可用性、不证明权限与并发安全（这些由实现与 QA1 的真实环境验证）；不出现真实幼儿姓名、面孔、园所或可识别信息。
