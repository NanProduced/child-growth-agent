# 芽芽 v1 核心契约｜yaya-v1.0（正式开发冻结）

2026-10-05，统一整合契约 b6b797d、技术 a87681a、设计 84af5f7。共同产品祖先 e8225f0。
本文件与 `src/lib/yaya/types.ts` 是下游核心口径；`contract-draft.md` 保留 R0–R2 历史。
**冻结的是接口语义，不是实现或生产认证通过**。本轮没有数据库迁移、真实模型、搜索、S3、浏览器或部署验收。

## 1. 产品与执行边界

- 芽芽是仅登录可用的幼教助手：一般问答、看图问答、范围内查询和全部已实现平台操作。
- 不绑定唯一幼儿；明确意图只读直查，真正歧义才澄清。多幼儿咨询先回答；显式记录意图才拆独立卡。
- 写入依照实际工作流人工核对，不对每个内部 SQL 弹确认。上传、聊天与私人准备内容可以持久化，但不自动形成业务观察。
- raw_text 保存后不可改写；AI 草稿与 confirmed_content 分离；指南引用/版本/成人帮助/三种正式状态沿用 G0/G5；不评分、排名或诊断。
- 未分配但有效的账号可一般幼教问答，不读园所私域；未登录、停用、身份不可用禁止全部模型调用。
- 管理员可管理/只读，不能教学确认。认证与范围授权复用 AUTH，模型、客户端及本地 runtime part 都不是授权事实。
- 已归档观察不能重新生成或再次归档。另一端先归档时保留私人草稿供对照，结束本次归档写入，不自动另建重复观察。

## 2. 已确定的技术路线

- assistant-ui 精确 0.15.23，LocalRuntime + 自有模型/附件/历史 adapters，多会话服务端持久化。
- 不实例化 AssistantCloud/遥测，不加第二状态库，不同时引 AI Elements。根 Zod 不因传递依赖而强制升级。
- 基于应用结构化动作的有界服务端循环：answer / read / clarify / propose_write；不是原生 Function Calling。
- read/propose_write 都校验白名单及参数。所有模型/工具尝试计预算；等待有上界，每次返回与派发前重查固定 run_id、取消、deadline、当前身份。
- UI abort、停止消费、上游物理取消分别报告。已开始业务写不会因关侧栏或停止模型而假称回滚。
- 文字与图片首版，不含语音/视频。私有图片服务端读取压缩后输入模型；真实选定模型视觉能力仍待授权 smoke。

## 3. 提案、批准与执行身份

1. 服务端准备时预分配 proposal_id、batch_id、每项 operation_id；客户端在可能写入之前持有完整身份。
2. 一个批准可绑定明确选中的 operation_id 集合；每个批准条目与执行条目一一对应，不得增加、替换或静默重放。
3. proposal_origin 保留模型/教师来源；只有经认证且 CSRF 保护的入口写入的 authenticated_entry 批准记录有效。
4. 批准保存当时的 actor/原 session、逐项动作/资源/目标、资源事实、内容 digest、附件关联、业务版本和生命周期快照。
5. 保存时比较 **批准快照、当前服务端事实、执行内容**。两个当前值一致，不代表旧批准仍有效；同权转班也失效。
6. 原 operation_id 的重复请求只返回其合法回执。读取/幂等重放先核对当前账号与 owner；读回不要求继承旧 session 批准，也不授权新写入。
7. 撤权、停用、目标修订、run 替换或批准取消后，迟到结果不能产生新动作。模型等待不持事务/行锁。

内容 digest 算法冻结为 SHA-256(UTF-8 规范 JSON)：由服务端对 schema 校验后的 payload、动作/资源/目标及附件关联计算；对象键排序，数组保持业务顺序，附件关联按 attachment_id/target_id 排序；拒绝重复附件、undefined、非有限数字及非 JSON 值。不规范化原文，不包含密码/令牌/签名 URL。本字段不能替代显式结构身份与资源版本检查；图片对象必须不可覆盖并绑定校验后的 checksum。

## 4. 回执、重试与替代操作

- 成功需合法状态/效果、非空白业务对象标识和完整身份；unknown 效果不能证明成功。unchanged 不要求 revision 递增。
- 查询按原 operation_id 和服务端预期身份核验；缺失/错配/矛盾/不完整成功证明均未知，不能任选第一条。
- `itemsToResend(plan, receipts)` 复用查询判定，仅输出已核验 failed+none，按 operation_id 去重；它是显式恢复候选，不是自动重发授权。
- 执行中、未知、查询失败、详情不可读：不新建替代执行。已提交则恢复原回执，详情失败只读重试。
- 明确无效果且需重新准备时：**短事务锁定旧操作→核验尚未开始→使旧操作/批准失效并记录 superseded_by→发布新操作**。旧迟到请求必须被拒绝；若旧操作已开始/已提交，替代失败，回到查询原操作。
- 业务变更、批准消费与最终回执须同一 client、同一真实事务；禁止独立记账、嵌套连接各自提交。模型不在事务内。
- 跨幼儿批次逐项结果；同一观察内归档与指南决定仍全有或全无。部分失败不重发整个批次。
- 成功回执描述原操作当时的结果；之后合法业务变化不改写历史成功，另列“当前状态后来更新”。不能用别人的当前业务状态证明自己的提交成功。

## 5. 图片、历史与隐私

- 未关联图片仅上传者；关联后按 record_kind+record_id 授权。full 可读字节，historical_read_only 仅元数据；多引用顺序无关。
- 文字原输入、教师补充、图片解读、已保存事实、指南/公开来源分开。AI 解读不直接升级为观察原文或正式指南依据。
- 图片可多人共同引用，不复制个体事实。删除会话不删除业务记录或仍被引用图片；查询引用不完整则禁止回收。
- 归档后允许追加**资料附件**，但不改 raw_text/confirmed_content、不自动形成指南依据；必须有独立追加审计、当前教师写权限和人工批准。具体存储/API 由 DATA1/MEDIA1 联合落地。
- 回收采用元数据删除租约：先锁定并标记 deleting，禁止新引用，再调用对象删除，最后落已删状态；外部删除结果未知时保留可核验标记。不得“查无引用→无保护物理删除”。
- 会话按账号私有（管理员不自动拥有他人聊天）；历史正文、附件、标题与模型上下文逐来源重新投影。
- 公开检索仅服务器确认不含幼儿识别信息时允许；provider 关闭或扫描未知不调用；不发送姓名、照片、原始观察。未知 usage 记 null，不填 0。

## 6. 下游接口与所有权

物理 SQL 字段、索引、存储 DTO 的内部细节由 DATA1 实现；它发布 `src/lib/yaya/storage-types.ts` 和 repository 接口，不能变更本核心契约。其他模块先做可注入依赖的真实核心代码，收到 DATA1 交付后装配；不能以永久 stub 宣称闭环。

| 接口族 | Owner | 固定语义 |
|---|---|---|
| `/api/yaya/conversations` 与 `[id]` | DATA1 | owner 私有列表/创建/改名/删除；GET 不续期、不产生模型请求 |
| `[id]/messages` | DATA1 | owner 私有保存/当前权限投影读取；client_message_id 幂等；恢复不执行 |
| `/api/yaya/proposals`、`[id]/approval` | DATA1 | 准备身份、CSRF 可信批准/拒绝/取消；不执行业务 |
| `/api/yaya/operations` GET | DATA1 | 当前 owner 按原身份查进行中/确定结果/未知 |
| `/api/yaya/operations` POST | TOOLS1 | 授权执行适配，同一事务消费+业务+回执；不与 DATA1 重复创建 route |
| `/api/yaya/uploads`、`[id]/content`、附件关联 | MEDIA1 | 私有媒体/逐引用授权/资料追加审计；DDL 与元数据 repository 归 DATA1 |
| `[id]/runs` | AGENT1 | 有界动作循环/流式事件；写入仅提案，确认执行另走 TOOLS1 |
| 聊天壳/消息/审批/附件 UI | UI1 | assistant-ui adapters 消费上述接口；视觉选稿批准后实现 |

账号私有写同样需要现有会话/CSRF 守门，但不虚构 AUTH action。业务执行走现有 runBusinessWrite。所有接口忽略客户端自报 Principal、scope、批准来源；具体 HTTP DTO/错误映射由 owner 给检查和交付，不在其他模块各自 fork。
