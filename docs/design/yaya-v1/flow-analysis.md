# Product Design 流程分析：卡点不是“操作失败”

目标：把“芽芽”从一句指令走到真实回执的每条路径拆开，逐段指出卡点属于**缺信息、权限、模型失败、结果不确定**中的哪一类，还是本来就**不是失败**（业务守门、空态、用户主动中止）。

证据标签：[C] 代码证据（基线 `e8225f0` 可核对）｜[A] 设计假设｜[U] 尚无教师实测（本设计没有任何真实教师测试）。

## 1. 角色与能力边界（设计前提）

| 身份 | 助手能做什么 | 不能做什么 |
|---|---|---|
| 教师（有任教班级） | 一般教育问答；范围内读；观察录入/整理/确认/指南决定/成长与活动链路 | 超出任教范围的资料；绕过确认的正式写入 |
| 教师（未分配） | 一般教育问答 | 任何园所私有资料读写 **[C] `src/lib/accounts/access.ts:40-43`** |
| 管理员 | 管理工具（班级、教师、任教、转班、建档基础信息）；范围内查看 | 教学动作：观察整理确认、指南决定、成长档案/活动支持写入；管理员录入观察被拒 **[C] `write-access.ts:33-40`、`access.ts:145-148`** |
| 未登录 | 只能看到登录引导 | 任何模型调用与私有资料 **[C] 需求 Q3；`access.ts:35-37`** |

## 2. 主流程与卡点分类

### S0 打开入口与身份恢复

- 用户目标：点右下角小芽，回到上次会话或直接提问。
- 系统责任：解析当前会话与范围；历史按当前账号投影。
- 卡点：**权限**（未登录/会话失效 401；身份服务不可用 503 fail closed）、**结果不确定**（另一设备/另一标签页状态冲突）、**用户主动**（关闭面板 ≠ 撤销任何已完成写入）。
- 设计回应：入口组件只展示“当前账号可达”的内容；401 出登录引导卡；503 出“身份服务暂时不可用”并禁用发送；切账号清空本账号私有投影（`recovery-spec.md` §9）。
- 证据：[C] `fetchWithAccountAuth` 在写请求前自查身份，401/503 直接返回，403 触发 `cga:auth-changed` **[C] `src/lib/accounts/client.ts:62-78`**；[A] 入口的展示形态。

### S1 一般教育问答（不绑幼儿）

- 用户目标：直接得到幼教问题的回答，不被要求先选对象。
- 系统责任：直接回答；引用公开权威来源时附真实出处；不出园所私有数据。
- 卡点：**模型失败**（超时/provider 报错/结构化输出非法）、**业务守门**（与幼教无关时温和收束，不是失败）。
- 设计回应：普通回答不进表单卡，**可多段、可长文、可展开来源**（短文本约束只用于进度/工具摘要）；失败时保留用户输入、允许重试；公开检索不携带幼儿姓名/照片/原文，查不到来源就如实说“查不到”，不编来源。 **[C] 需求 Q10；PRODUCT.md Web 查询约束**
- 证据：[C] `src/lib/llm.ts:347-420`（超时、HTTP 错误、空内容都会抛错，不静默成功）。

### S1b 看图问答与临时观察准备（R1 新增）

- 用户目标：上传作品/活动图后直接问，或先把观察素材放在手边，不先建观察。
- 系统责任：登录即可使用；不要求先选幼儿、不要求 ≥10 字原文；图片解读标注来源；只有显式记录意图才进入准备卡；即使进入准备卡也不自动写库。
- 卡点：**权限**（三层：登录、角色范围、账号状态；停用/失效/身份不可用关闭全部模型）、**模型失败**（图片分析失败不阻塞后续行为）、**缺信息**（仅在写入准备时才收集对象/日期/原文）。
- 设计回应：回答后提供可选 `准备为观察`；**多名幼儿的分析先回答**，只有显式记录/分别记录意图且事实映射明确才生成独立卡，真正重名/指代/映射不明才澄清；AI 解读与教师事实分离。 [R1][R2]
- 证据：[A] 图片能力未实现；正式整理链路 [C] `review-client.tsx`、`src/app/api/observations/route.ts`。

### S2 范围内事实查询

- 用户目标：“小满这学期有哪些已确认观察？”
- 系统责任：经当前范围服务端读；回答标明来源与统计口径。
- 卡点：**权限**（403 out_of_scope；管理员可查但不可教学）、**基础设施**（DB 读取失败 ≠ 零记录）、**空态**（真的没有记录）。
- 设计回应：回答中区分“没有记录”“未获取”“读取失败”；读取失败给重试而不是 0。 **[C] PRODUCT.md：`null`=未获取、0=真实零；首页四态文案；`children/[id]/page.tsx:176、212`“这不代表没有数据”**
- 证据：[C] `src/lib/accounts/access.ts:140-156`（先判角色/范围再泄露存在性）。

### S3 观察录入准备（表单或聊天内）

- 触发：**显式记录/准备为观察意图**；分析或咨询不自动进入。 [R2]
- 用户目标：把刚看到的行为保存成一条观察，不被迫跳多个页面。
- 系统责任：只收集完成动作所需信息；原文 ≥10 字；保存后不可改写；日期与发生时班级按分班历史核对；准备态可账号私有持久化，但不自动形成业务观察。 [R2]
- 卡点：**缺信息**（幼儿、日期、原文；发生时班级无法自动确定时需要一次显式选择）、**结果不确定**（选择班级后班级资料又变化 → `class_context_conflict`，必须重新核对）、**权限**（管理员/未分配教师不能录入）。
- 设计回应：准备卡内联补全，不跳页；班级核对三态（核对中/已核对/需选择）+ 失败重试；保存失败保留输入。 **[C] `new-observation-client.tsx:181-212、269-283`**
- 证据：[C] `src/app/api/observations/route.ts:93-113`（409 需确认/400 资料不可核实/409 冲突）。

### S4 图片上传与分析

- 用户目标：把照片放进记录，或者问“这画的是什么？”
- 系统责任：上传、分析、保存、归档四件事分开反馈；图片是资料与素材，不自动成为幼儿身份或发展事实；**保存前允许看图问答与模型解读**（服务分层见 `brief.md` §1.1），正式整理只在原文保存后启动。
- 卡点：**基础设施/模型失败**（上传失败、分析失败、链接过期）、**结果不确定**（分析输出可能有误，不能当作观察事实）、**缺信息**（这张图关联谁、关联哪条记录需要教师选择）。
- 设计回应：逐图状态与重试；分析失败仍可继续文字观察；教师事实描述与 AI 解读来源分开；拍摄时间/人脸不成为观察日期/身份；图片解读不自动关联记录。 **[C] 需求全文 §3.4、§5；[R1]；[U] 图片能力当前完全未实现**（基线 `src/` 无 upload/S3/sharp/attachment 代码，grep 0 命中）。
- 证据：[C] 现状缺口；未来 DTO 由 YAYA0-CONTRACT / YAYA-MEDIA1 定义。

### S5 AI 整理与必要追问

- 用户目标：得到一张可核对的草稿。
- 系统责任：按五大领域整理；只在补充会影响分析质量时提问；最多 2 轮；可跳过、可停止。
- 卡点：**模型失败**（超时/非法输出）、**缺信息**（needs_input）、**业务守门**（追问是设计而非失败）。
- 设计回应：追问卡内联回答/跳过/停止；跳过不阻塞其他条目；整理失败原文不丢。 **[C] `review-client.tsx:794-878`（第 x/2 轮、回答/跳过/不再追问）、`types.ts:3`**
- 证据：[C] `src/lib/follow-up.ts`（旧记录问题缺失时不补造）。

### S6 教师修改与澄清

- 用户目标：改完 AI 草稿就归档。
- 系统责任：教师改动先经修改审核；审核结果绑定当前内容快照，改动后旧审核失效。
- 卡点：**业务守门**（clarify 不是失败，是证据不足）、**结果不确定**（审核结果与当前内容不匹配）。
- 设计回应：审核卡区分“已理解可归档/需澄清”；澄清失败保留输入；不静默覆盖教师修改。 **[C] `review-client.tsx:1035-1176`、`types.ts:120-135`**
- 证据：[C] `teacher_edit_review` 结构化输出 **[C] `src/lib/llm.ts:92-113`**。

### S7 指南决定

- 用户目标：把观察关联到具体年龄表现条目。
- 系统责任：只对应具体条目；三种正式状态；AI 建议只是工作流状态；每一条必需依据都要有效。
- 卡点：**结果不确定**（依据失效 `basis_expired`、目录版本变化 `catalog_version_mismatch`、状态冲突）、**业务守门**（成人帮助规则决定“表现/线索”，不是错误）、**缺信息**（需要选择引用片段与依据来源）。
- 设计回应：决定卡带条目规则与逐字引用；陈旧决定要求重新核对或移除，不自动重放；AI 建议失败不阻塞手动关联。 **[C] `review-client.tsx:440-448、471-483`；`association-types.ts:141-219`**
- 证据：[C] 需求 §3.6 与 `docs/guide-evidence-v1/contract.md`（只读引用）。

### S8 批准与执行

- 用户目标：让已经核对的动作真正发生。
- 系统责任：批准绑定具体内容+对象；服务端执行；模型不能自行放行。
- 卡点：**结果不确定**（网络中断后保存与否未知；另一端已归档 409；响应到达但内容无法证明生效；原操作可能仍在进行中）、**权限**（撤权/转班/停用后迟到写入被拒）。
- 设计回应（R2）：按 `recovery-spec.md` 六类分型；成功 = 原操作成功 + 身份/内容/业务结果核对一致；结果未知只查原 `operation_id`，不自动重复提交、不新建提案绕过核验；另一端归档不同内容不显示“你的修改已保存”；批准后修改内容则旧批准失效；关闭聊天 ≠ 回滚，后台操作不显示成已撤销；上传/准备/审核等中间效果不冒充整条归档成功。 **[C] `review-client.tsx:292-328、427-462、497-513`；`access.ts:195-222`；[R1][R2]**
- 证据范围修正：现有“重新读取核对”读的是**观察业务状态**（`GET /api/observations` 判断是否 confirmed），不是通用 `operation_id` 回执账本，无法区分“进行中/未落地/未发送”，也无法证明归属与一致性。通用操作身份与回执查询 **[A] 依赖 CONTRACT-R1**（最终命名交 YAYA0），UI 不自定义恢复算法。 [C] `review-client.tsx:292-328`
- 证据：[C] `runBusinessWrite` 事务内复核身份与归属变化。

### S9 多人批次

- 触发：**显式记录/分别记录意图** + 多名幼儿的不同事实；仅分析/咨询不建卡。 [R2]
- 用户目标：一个活动里几个孩子的行为各自成卡。
- 系统责任：一张共同照片可关联多条记录；不把群体描述复制成每人事实；逐条核对、逐条保存、逐条回执。
- 卡点：**缺信息/结果不确定**（其中一条待补充或失败，其余照常）、**业务守门**（未勾选不保存）。
- 设计回应：批次 = 独立卡列表 + 勾选保存；每项独立落入六类（已保存/明确失败/冲突/结果未知/待补充/未开始）；只对“明确失败无效果”项重试；已保存项不重发；冲突项重新核对。 **[C] 需求 Q7、§3.4；[R1]**
- 证据：[A] 批次是设计假设最重的一段；[U] 无教师实测批量核对负担（需求 §8 Q7 保留复议）。

### S10 归档与档案回看

- 用户目标：确认后能在成长档案看到记录与图片。
- 系统责任：确认稿进正册；成长小结只由已确认观察更新；成长小结更新失败 ≠ 观察归档失败。
- 卡点：**部分失败**（档案更新失败）、**结果不确定**（已保存但详情暂时读不到）、**空态**（暂无确认观察是正常）。
- 设计回应：回执把“观察已归档/档案已更新/指南关联已写入”分开说；详情失败显示“已提交、详情暂不可读，请勿重复提交”；中间效果不冒充整条归档成功。 **[C] `review-client.tsx:497-528、758-762`；[R2]**
- 证据：[C] `children/[id]/page.tsx:232-256`（汇总只取已确认；fallback 标注）。

### S11 历史会话恢复与权限变化

- 用户目标：换设备接着聊。
- 系统责任：默认账号私有；恢复不自动重做写入；撤权后历史内容受限，聊天历史不能绕过权限。
- 卡点：**权限**（账号切换、撤权、转班后旧内容投影；账号状态与身份可用性）、**结果不确定**（恢复时刻的写入状态）。
- 设计回应（R1 分型）：
  - 撤权/转班但账号有效：可一般幼教问答；业务对象按范围说明，不渲染旧数据。
  - **账号停用、会话失效、身份服务不可用：全部模型调用关闭（含一般问答），不只隐藏教学按钮。**
  - 同账号范围变化 → 相关业务来源按新范围重新投影；换账号 → 立即清空前一人的草稿、图片、消息、待提交选择，不闪现。
  - 恢复只恢复“对话”，不恢复“执行”：显式继续需当前身份 + 最新前提 + 新批准；runtime 因新消息取消旧 tool part 时，业务草稿不随之丢失（映射依 TECH0/CONTRACT）。
  - 受限历史显示受限投影，不泄漏。 **[C] `review-client.tsx:236-263` viewerKey 清空模式；需求 §5；[R1]**
- 证据：[C] 需求 §5；[A] 历史受限投影与通用操作身份的具体边界待 CONTRACT-R1。

## 3. 卡点分类总表（禁止全都写成“操作失败”）

| 类别 | 典型信号 | 界面必须有 | 反面（禁止） |
|---|---|---|---|
| 缺信息 | 未选幼儿/日期、原文过短、需要选班级、追问、需要引用片段 | 卡内补全位与“为什么需要” | 把缺信息渲染成红色失败 |
| 权限 | 401/403/503、empty_scope、管理员教学动作 | 明确身份原因 + 下一步（登录/联系管理员/只读） | 伪装成空数据；泄露资源存在性 |
| 模型失败 | 超时、provider 错误、输出非法 | 保留输入、可重试、原文不丢 | 倒空输入框；把模型失败显示为“已完成” |
| 结果不确定/冲突/进行中 | 网络中断、409、版本变化、原操作未结束、已提交详情读不到、批量混合 | 六类分型（明确失败/冲突/结果未知/执行中/已提交详情暂不可读/批次分项）；未知只查原 operation_id；成功需身份/内容/结果一致 | 一律叫“待核对”；自动重发；新建提案绕过核验；他人写入显示成自己的成功；执行中锁全会话 |
| 业务守门 | 修改审核 clarify、依据失效需重新核对、成人帮助规则 | 中性说明 + 重新核对/澄清入口 | 把守门说成系统故障或失败 |
| 空态 | 无幼儿、无观察、无历史、无指南记录 | 如实零值 + 下一步 | 空态与读取失败混用；0 与 null 混用 |
| 基础设施 | DB/身份服务不可用 | “暂未读取，不代表没有数据”+重试 | 显示 0 或缓存旧值 |
| 用户主动 | 跳过、停止、关闭面板、取消上传 | 保留已完成写入；说明不撤销 | 暗示关闭=回滚；弹确认阻断 |
